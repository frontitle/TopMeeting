# 会议资料库与总结质量改进

状态：以下分阶段方案，未标注“已实现”的部分尚未接入客户端。

## 资料库

已实现：今天/近 7 天/更早分组，全部/已总结/待总结筛选，多关键词搜索标题、正文、纪要、语境和说话人。最近删除与正常资料隔离。

下一阶段：项目/客户归档作为主分类，系列会议作为跨日期集合，标签作为多维筛选；不要让项目与标签各自复制一份会议。加入搜索命中片段、日期/人物筛选，点击结果跳到原文或录音时间。

存储阶段：从整库 JSON 改为 SQLite 事务存储、全文索引、分页列表与按会议加载正文。中文分词、标点归一和人名别名要有固定测试集。录音、附件、索引分开管理；删除先进入回收站，清理音频需要明确策略。向量检索作为可选补充，不能替代关键词与时间过滤，也不默认把历史会议上传模型。

验收目标：以合成的 1 万场会议测启动、查询延迟、内存及增量保存；目标值需要基准测试后设定。当前线性检索和 JSON 存储尚未完成该规模验收。

## 总结结果

1. 议题先行：从发言中组织议题、观点、依据、决定与待办，避免把同一观点多次复述。
2. 证据绑定：每个结论保留段落 ID、修订版本、时间戳与说话人；原文改动后标记相关总结过期。
3. 状态区分：提议不自动变成决定；分歧保留各方观点；负责人、截止时间和数值缺失时标为待确认。
4. 增量更新：发送新增、修改和删除的段落，加上受影响议题的已有摘要；返回带版本的补丁。客户端拒绝过期版本、无来源和重复补丁。`packages/core` 已提供补丁验证基础，但还没有接入模型请求或原生 UI。
5. 呈现：会中保持结构化议题卡片，表格用于明确对比，图表只使用有原文依据的数值。会后完整总结再在飞书文档绘制核心信息画板。
6. 成本控制：保留按需更新与会后一次总结；不恢复每 30 秒全量重写。将来实时模式以新增内容量、议题变化、冷却时间和请求预算共同约束，并提供用户开关。

模型评测：使用授权录音与人工参考稿，比较事实正确率、关键信息覆盖、待办准确率、来源可追溯率、重复率和实际 token 用量。不得把生成字数或图表数量当成准确率。测试不同模型时使用同一输入快照。
